# Authentication API Handoff

## Overview

The authentication system supports two authentication methods:

1.  **Biometric Authentication** (Fingerprint / Face ID)
2.  **PIN Code Authentication**

The backend never receives biometric data. Biometric verification is
performed entirely on the device using the operating system's secure
APIs. The server only verifies a cryptographic signature generated by a
private key stored in the device's secure hardware.

## Authentication Flow

``` text
                 User
                   |
                   v
        Authentication Screen
                   |
        +----------+----------+
        |                     |
        v                     v
   Fingerprint            Enter PIN
        |                     |
        v                     v
 Local biometric         User input
 verification
        |                     |
        v                     v
Generate signature      Validate PIN
        |                     |
        +----------+----------+
                   |
                   v
        Authentication Service
                   |
                   v
      Access Token + Refresh Token
```

## Initial Device Registration

1.  User logs in using a primary authentication method (password/OTP).
2.  Device generates a public/private key pair.
3.  Private key remains in secure hardware.
4.  Client sends the public key to `/auth/register-device`.
5.  Backend stores `userId`, `deviceId`, and `publicKey`.

## Endpoints

  ------------------------------------------------------------------------
  Endpoint                   Method                Purpose
  -------------------------- --------------------- -----------------------
  `/auth/register-device`    POST                  Register device public
                                                   key

  `/auth/challenge`          POST                  Generate one-time
                                                   authentication
                                                   challenge

  `/auth/biometric`          POST                  Authenticate using
                                                   biometric signature

  `/auth/pin`                POST                  Authenticate using PIN

  `/auth/refresh`            POST                  Refresh access token

  `/auth/logout`             POST                  Revoke session
  ------------------------------------------------------------------------

## Biometric Authentication

### Request Challenge

``` http
POST /auth/challenge
```

Response:

``` json
{
  "challengeId": "uuid",
  "challenge": "base64-random-string"
}
```

### Authenticate

``` http
POST /auth/biometric
```

``` json
{
  "deviceId": "...",
  "challengeId": "...",
  "signature": "..."
}
```

Backend: - Validate challenge. - Verify signature using stored public
key. - Issue access and refresh tokens.

## PIN Authentication

``` http
POST /auth/pin
```

``` json
{
  "deviceId": "...",
  "pin": "123456"
}
```

Backend: - Verify hashed PIN. - Check lock status. - Issue JWT tokens.

## Token Refresh

``` http
POST /auth/refresh
```

``` json
{
  "sessionToken": "..."
}
```

Response:

``` json
{
  "accessToken": "...",
  "sessionToken": "..."
}
```

The session token is rotated on every refresh: the one sent in the request
is revoked and a new one is returned. The client must persist the returned
`sessionToken` and send that one next time, or it will be logged out.

## Logout

``` http
POST /auth/logout
```

## Security

-   Never send biometric data to the backend.
-   Store private keys only in Android Keystore or Apple Secure Enclave.
-   Store only public keys on the backend.
-   Challenges must be single-use and expire within 60--120 seconds.
-   Store PINs using Argon2id or bcrypt.
-   Use HTTPS/TLS.
-   Rotate refresh tokens.
-   Apply rate limiting and account/device lockout after repeated
    failures.
